## 2. 실행 방법

1. IPYNB와 ZIP을 같은 폴더에 둔다. Colab에서는 왼쪽 파일 패널에 ZIP을 올리거나 본인 Drive에 두고 `BASE_DIR`을 그 폴더로 지정한다. Drive 사용 시 본인이 먼저 Drive를 마운트한다.
2. Python 3.11 이상 환경에서 노트북의 셀을 위에서 아래로 실행한다. GPU는 필요하지 않다. 첫 실행은 필요한 패키지를 설치하므로 인터넷 연결이 필요할 수 있다. 패키지가 이미 있으면 설치하지 않는다.
3. 기본 설정을 유지하면 Test A 100척·58,189시간대와 Test B 100척·82,626시간대의 확정 결과를 재현한다.
4. `RUN_HOLDOUT_EVALUATION=True`이면 1,477척·801,973시간대 전체를 다시 예측해 지표를 계산한다. CPU·저장장치에 따라 수 분 걸릴 수 있다. 최소 4GB 이상의 사용 가능 메모리와 ZIP 압축 해제 공간을 권장한다.
5. `RUN_NEW_B_EXAMPLE=True`이면 별도 재학습 모델로 3척의 새 입력 예제를 실행하고 과거 시점 추론 차단·미래 관측 배제도 검사한다.
6. 결과는 `outputs/final_run_날짜_시각/`에 저장된다. 기존 모델과 원래 입력은 덮어쓰지 않는다.

노트북은 새 Python 작업 프로세스에서 모델을 실행한다. 라이브러리를 설치하기 전 커널에 로딩돼 있던 버전과 혼합하지 않기 위한 구성이다. 검증한 버전은 NumPy 2.4.6, pandas 2.2.3, PyArrow 25.0.1, LightGBM 4.6.0, scikit-learn 1.7.2, joblib 1.6.0, SciPy 1.18.1이다. 의존성은 ZIP의 requirements에도 있다. Mac에서는 scikit-learn의 OpenMP 라이브러리 경로를 작업 프로세스에 전달한다. 그 라이브러리가 없는 배포 환경에서는 운영체제에 맞는 libomp가 필요하다.

## 4. 과제 1 모델 설계

### 기본 특징 50개

항적 모양 31개, 관측 특성 9개, 위치 6개, 달·시간의 주기 인코딩 4개다. 주요 값은 이동거리·직선성·선회·분포·좌표 범위·점/구성선 수 등이다.

거리는 반지름 6371.0088km의 구면 기준이다. 방향 변화는 도 단위다. 선회 민감도는 원시·5m·20m·100m 기준을 따로 계산하며 양쪽 연속 선분이 기준을 만족하는 쌍만 사용한다. MultiLineString 구성선을 서로 연결하거나 좌표를 재정렬하지 않는다. 좌표별 정확한 시각이 없으므로 추정 속도·가속도를 만들지 않는다. 정의할 수 없는 특징은 NaN으로 보존하고 LightGBM이 결측을 처리한다.

**원시 WKT→50개 특징을 만드는 원래 추출 스크립트는 전달된 ZIP에 없었다.** 이 패키지는 검증된 파생 특징을 포함하고, 새 입력도 같은 특징 계약을 받는다. 원시 `geom` CSV를 즉시 읽어 끝까지 처리하는 노트북으로 설명하지 않는다. 새 원시 파일을 쓰려면 같은 정의의 특징 추출기를 먼저 준비하고 기존 특징과 대조해야 한다. 50개 특징의 정확한 이름·단위·결측 원칙은 `schema/feature_catalog.json`에 있다.

### 과거 요약 79개

각 선박의 경로 길이·직선성·20m 선회 평균·회전반경·반복 선분 비율·점 수, 총 6개 제어 특징을 사용한다. 6·12·24시간마다 과거 평균·모표준편차(ddof=0)·현재값과 과거 평균의 차이·유효 개수를 계산한다. 창별 관측 개수와 관측 비율도 추가하고, 직전 관측과의 시간 간격 1개를 더한다.

`3 × (6 × 4 + 2) + 1 = 79`이며 현재 50개와 합쳐 129개다. 창은 `[현재시각-창길이, 현재시각)`로 현재·미래를 제외한다. 자신의 모든 관측으로 계산한 후 표본을 선택하며 보간·미래 채움은 하지 않는다. 새 데이터에 과거 관측이 빠지면 요약값도 달라진다.

이전 시간 특징 생성 코드도 일부 누락돼 정의에 맞춰 재구현했고, 저장 캐시 40척·4,126표본에서 float32 방식·결측 패턴·수치를 대조했다. 최대 절대 오차 약 0.00000382, 상대 허용오차 0.000002·절대 허용오차 0.00002를 통과했다. 제공 Test A 전체 시간 특징도 독립 대조했다.

### 학습·선택과 최종 추론

기존 학습 선박 4,422척에서 선박 단위 3-fold 개발 검증을 했다. 선박이 학습·outer 평가에 섞이지 않도록 역할을 나눴다. 학습 시 선박 관측량 역수와 클래스별 선박 수에 대한 0.5 지수 가중을 적용한 `past129_power0.5` 후보가 선택됐다. 조기 종료·온도·후보 선택에는 각 fold의 내부 역할을 사용했다. 예측 결과를 본 outer fold로 해당 fold 모델을 선택하지 않았다. 다만 개발 CV를 반복 관찰한 실험이므로 완전히 새로운 독립 시험은 아니다.

최종 모델은 다음과 같다.

| 모델 | 선택 소스 | 온도 T | 앙상블 비중 |
| --- | --- | --- | --- |
| fold 0 | baseline | 1.0 | 1/3 |
| fold 1 | regularized | 1.3 | 1/3 |
| fold 2 | baseline | 1.0 | 1/3 |

온도 보정은 `q = softmax(log(clip(p, 1e-12, 1)) / T)`다. 보정 확률을 3개 모델에서 동등 평균한 뒤 선박의 관측 시간대 확률도 동등 평균한다. 최댓값의 클래스를 조업형태로, 그 값을 예측 확률로 저장한다. 클래스 순서는 자망·통발·연안복합·채낚기연승낚시다. ID·조업 정답·사고 자료는 예측 특징으로 사용하지 않는다.

통발 전용 모델 추가는 3개 fold 모두 개선하지 못해 사용하지 않았다. 최적화도 OOF 시간대 Macro F1 기준 약 0.149%p 개선에 그쳤다. 새로운 최적화·가중치 변경·전체 자료 재적합을 이 노트북에서 수행하지 않는다.

### 점수와 해석

기존 holdout 1,477척·801,973시간대에서 선박 Macro F1은 **54.33%**, 선박 정확도는 **56.87%**, 선박 균형 시간대 Macro F1은 **51.62%**다. 클래스별 선박 F1은 자망 47.36%, 통발 34.23%, 연안복합 65.94%, 채낚기연승낚시 69.77%다. 마지막 클래스는 33척으로 적다.

holdout은 이전 단계에서 이미 관찰된 자료이며 대회 공식 Test 성적이 아니다. 54.33%는 F1의 백분율이지 대회 100점 만점 환산 성적이 아니다. 공식 Test A 정답은 없다. Test A 100척 중 46척은 원래 학습 선박 ID와 겹치지만 ID로 정답을 찾아 예측을 대체하지 않았다. 템플릿 예시 라벨도 정답으로 쓰지 않는다.

## 5. 과제 2 모델 설계

### 네 가지 성분

| 성분 | 계산 방식 |
| --- | --- |
| peer | 이동 모양 27개에 IsolationForest 100개 트리·max_samples=256. 결측 대치값과 결측 지시자를 사용 |
| personal | 자신의 과거 720시간 중앙값·IQR에서 현재 관측이 얼마나 벗어났는지 측정. 지역 척도가 없으면 학습 구간의 전역 척도로 대체 |
| space | 자신의 과거 720시간 위치 중앙값에서 현재 위치까지의 구면 거리 |
| change | 직전 관측과 현재 제어 특징의 차이를 전역 척도로 정규화. 관측 간격 1~2시간에서만 사용 |

개인 기준에는 과거 관측 24개 이상·서로 다른 날짜 3일 이상을 요구하고, 특징별 과거 유효값은 12개 이상이어야 한다. personal·change는 가용 제어 특징 3개 이상이 필요하다. 현재·미래 시점은 개인 과거 기준에 넣지 않는다. 각 시간대의 항적은 시간대 종료 후에 완성되므로 시간대 종료 전 경보로 해석하지 않는다.

각 월의 모델 적합은 cutoff 기준 `[cutoff-744h, cutoff-168h)`, 보정은 `[cutoff-168h, cutoff)`의 항적 종료시각을 사용했다. 적합 참조는 선박당 64개로 제한했다. 1월은 준비 기간으로 남겼고, 2~6월 모델 5개로 과거 평가를 수행했다. 이 최종 패키지의 새 입력 추론에는 최신 **June 2026 모델 한 개**를 동결해 넣었다.

성분의 raw 값을 과거 보정 자료의 경험적 CDF(midrank)로 0~1에 대응시키고, 유효 성분만 평균해 상대 이상점수를 만든다. 성분 조합별 보정 자료 99% 분위수를 임계값으로 사용한다. 조합 표본이 100개 미만이면 같은 성분 수, 다시 부족하면 전체 보정 자료로 대체한다. 임계값을 엄격히 초과한 관측이 같은 선박의 정확히 연속한 두 시간대에 나타나면 두 번째 시간대에 경보를 낸다. 공백을 건너뛰어 연속으로 취급하지 않는다.

### 확정 결과 재현과 새 입력 추론의 구분

**기본 B 모드**는 기존 최종 Test B의 성분을 평균해 확정 점수를 재현한다. 이전 결과 100척·82,626시간대와 일치한다. 원래 2026년 June 모델 파일·보정 배열이 전달 자료에 없어서 그 모델로 raw 추론을 다시 수행할 수 없었다. 확정 점수의 출처와 이 한계를 ZIP manifest에도 기록했다.

**새 B 입력 모드**는 2026-11-01에 동일 대회 자료와 원래 파라미터로 다시 학습한 June 모델을 사용한다. 새 모델을 원래 Test B 모델인 것처럼 대체하지 않는다. 별도 파일명·별도 model_origin으로 저장한다. 사용자 입력이 모델 cutoff보다 이르면 기본적으로 오류로 차단한다. 입력 중 `NEW_B_TARGET_START` 이전 관측은 개인 이력으로만 사용한다.

이번 전체 재학습에서 연속 경보 수는 기존 1,171→1,167시간대였고 경보 여부가 달라진 행은 14개였다. 원래 scorer의 실수 동점 판정에 민감한 CDF 때문에 차이가 확대됐다. 보정·대상 raw 값을 모두 소수 12자리로 반올림하면 1e-6를 넘는 점수 차이는 20행으로 줄었으나 완전 동일하지 않았다. 새 입력 모드는 12자리 규칙으로 CDF와 보정 임계값을 함께 계산한다. 고정 모델·전처리·런타임을 함께 보존해야 한다.

### 과제 2의 점수 한계

확정 사고 ID·실제 사고시각·정상/사고 구간 라벨과 공식 산식이 없어 사고 정밀도·재현율·탐지 선행시간·공식 점수는 산출할 수 없다. 경보 횟수·최고점수·평균 이상점수를 성능 점수로 바꾸지 않는다. 이상점수는 사고확률이 아니다. 최고점 시각도 확인된 사고시각이 아니다.

제공 Test B는 2025년인데 원래 기준은 2026년 June 모델이었다. 이는 사후 분석이며 2025년 당시의 인과적 조기 탐지 성능이 아니다. 새 입력 예제에서는 적합 이후의 2026년 6월만 평가하고 과거 시점 적용을 기본 차단한다. 이 역시 사고 라벨에 대한 탐지 성능 검증은 아니다.

## 6. 새 입력 사용법

### 과제 1

`CUSTOM_TASK_A_FEATURES`에 CSV/Parquet 경로를 넣는다. `rfid_id`는 문자열로 유지하고 각 선박·시간 키는 유일해야 한다. `hour_start`는 Unix epoch 이후의 정수 시간이다. 이것이 없으면 `part_dt`(YYYYMMDD)와 `rfid_time`(0~23)으로 계산한다. 원 자료의 타임존이 확정되지 않아 날짜를 임의로 UTC/KST 이동하지 않는다.

특징은 `schema/classification_model.json`의 129개 전체 또는 앞의 기본 50개를 제공한다. 과거 특징 79개 중 일부만 제공하는 입력은 거절한다. 50개만 제공할 때는 점수 대상 이전의 자기 선박 관측도 함께 제공해야 한다. 기본 특징의 단위·정의가 다르면 같은 이름이어도 모델에 바로 넣으면 안 된다. NaN은 유지하고 무한대·비수치 값·중복 키는 오류로 처리한다.

최종 결과를 동일하게 재현하려면 제공된 **129개 완성 특징 입력**을 사용한다. 50개에서 과거 특징을 다시 계산하는 경로는 실수 반올림과 트리 분기 경계 때문에 기존 확률과 완전히 같지 않을 수 있다. 추가 검사에서 Test A 100척의 최종 라벨은 모두 같았으나, 일부 시간대 클래스 확률의 최대 차이는 0.0317335였다. 50개 입력 경로를 기존 확정 확률의 완전 재현 경로로 사용하지 않는다.

### 과제 2

`CUSTOM_TASK_B_FEATURES50`에 같은 기본 50개 특징과 선박·시각을 제공한다. `NEW_B_TARGET_START`를 점수를 낼 시작시각으로 설정한다. 이전 관측은 개인 이력으로만 쓴다. 과거 720시간을 충분히 포함하지 않으면 성분이 줄고 low_support가 늘 수 있다. `ALLOW_NEW_B_BACKCAST=False`를 유지하면 June 2026 모델보다 이른 대상은 차단된다. True를 명시하면 사후 분석이며 인과적 평가로 표시하지 않는다. 개인 이력은 제공 자료 내에서만 계산하므로 누락된 항적을 복원하지 않는다.

새 입력은 사전에 정의된 특징 계약에서 시작한다. 원시 WKT 추출·전체 4,422척 분류 재학습·전체 월별 이상모델 재학습을 이 노트북의 기본 기능으로 포함하지 않았다.

## 7. 출력과 검증

- `task_a_predictions.csv`: 선박별 클래스 확률 p0~p3, 예측 라벨·확률·관측 시간대 수.
- `task_a_hourly_probabilities.parquet`: 시간대별 4개 분류 확률.
- `task_b_frozen_hourly_scores.csv`, `task_b_frozen_peak_times.csv`: 원래 확정 B 점수와 최고점 시각.
- `task_a_holdout_vessel_predictions.csv`, `evaluate_summary.json`: 실제 재실행한 검증 예측·정답·지표.
- `task_b_rebuilt_demo_*.csv` 또는 `task_b_rebuilt_new_input_*.csv`: 명시적으로 별도 재학습 모델을 사용한 새 B 추론 결과.
- `run_manifest.json`: 입력·모델 출처·런타임·재실행 여부·공식 점수 미산출 기록.

패키지에서 모든 입력·모델 해시를 확인한다. 기본 A는 원래 100척의 라벨·확률을 대조하고, 기본 B는 성분 평균과 저장 점수를 대조한다. holdout은 3개 핵심 지표를 기준 지표와 대조한다. 새 B 예제는 과거 시점 차단과 prefix 불변성을 검사해 미래 관측 추가가 이전 점수에 영향을 주지 않는지 확인한다. `RUN_HOLDOUT_EVALUATION=False`인 경우 저장된 지표를 새로 실행한 성적으로 표시하지 않는다.

기존 제출 엑셀은 B 템플릿 9열을 8,507열로 확장한 후보였다. 공식 시스템의 열 확장 허용 여부는 확인되지 않았다. 노트북은 이 엑셀을 다시 공식 확정본으로 만들지 않고 A 선박별 CSV·B 시간대별 CSV를 생성한다. 공식 제출 양식과 산식이 확인되면 그 계약에 맞는 변환·확인이 필요하다. 온라인 제출은 수행하지 않는다.

## 8. 최종 파일 실행 검증 기록

최종 ZIP만 별도 임시 폴더에 복사하고 압축을 풀어, 전달 노트북의 순수 Python 코드 셀 8개를 순서대로 실제 실행했다. 모든 셀이 통과했다.
